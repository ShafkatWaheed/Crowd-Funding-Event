# Crowd Funding Event — Start Commands

Run these in separate terminals. Ensure .env is configured before starting the backend.

---

## Quick Start (PostgreSQL + Redis)

  # Start both services with one command (creates containers on first run)
  sudo ./scripts/start_services.sh

  # Or from project root:
  sudo bash scripts/start_services.sh

## Backend (FastAPI)

  cd Backend
  source venv/bin/activate
  uvicorn app.main:app --reload --host 0.0.0.0 --port 8000

  (On Windows, use: venv\Scripts\activate)

  API: http://localhost:8000
  Docs: http://localhost:8000/docs

## Database Migrations (Alembic)

  cd Backend
  source venv/bin/activate

  # Apply all pending migrations
  alembic upgrade head

  # Check current migration version
  alembic current

  # View migration history
  alembic history --verbose

  # Create a new migration (auto-generate from model changes)
  alembic revision --autogenerate -m "description_of_change"

  # Rollback one migration
  alembic downgrade -1

  # Rollback all migrations
  alembic downgrade base

  One-liner (from project root):
  cd Backend && source venv/bin/activate && alembic upgrade head

## Redis (Docker)

  # First time — pull and start Redis container
  sudo docker run -d --name redis -p 6379:6379 --restart unless-stopped redis:7-alpine

  # Verify it's running
  docker exec redis redis-cli ping
  # Should return: PONG

  # Start Redis (if container exists but is stopped)
  sudo docker start redis

  # Stop Redis
  sudo docker stop redis

  # Check status
  docker ps --filter name=redis

  Config: REDIS_URL=redis://localhost:6379/0 (in Backend/.env)
  Note: The app works without Redis — emails won't send and ARQ tasks are skipped,
        but refunds still complete inline. Redis is required for background emails
        and future payment gateway integration.

## ARQ Worker (Background Tasks)

  cd Backend
  source venv/bin/activate

  # Foreground (see logs in terminal):
  arq app.worker.main.WorkerSettings

  # Background (logs to file):
  nohup ./venv/bin/python -m arq app.worker.main.WorkerSettings > /tmp/arq_worker.log 2>&1 &

  # View logs:
  tail -f /tmp/arq_worker.log

  # Stop:
  pkill -f "arq app.worker.main.WorkerSettings"

  Requires Redis to be running.
  Handles: email sending, refund processing, escrow, bank verification (26 tasks).
  Run in a separate terminal alongside the backend.

## Firebase Chat Listener (Real-time)

  cd Backend
  source venv/bin/activate

  # Foreground (see logs in terminal):
  python3 -u -c "
from app.worker.firebase_chat_listener import start_listener
import time, signal, sys

def handle_signal(sig, frame):
    print('Listener shutting down', flush=True)
    sys.exit(0)

signal.signal(signal.SIGTERM, handle_signal)
signal.signal(signal.SIGINT, handle_signal)

start_listener()
print('Firebase chat listener running.', flush=True)

while True:
    time.sleep(60)
"

  # Background (logs to file):
  cd Backend && source venv/bin/activate && nohup python3 -u -c "
from app.worker.firebase_chat_listener import start_listener
import time, signal, sys
signal.signal(signal.SIGTERM, lambda *a: sys.exit(0))
start_listener()
while True:
    time.sleep(60)
" > /tmp/firebase_listener.log 2>&1 &

  # View logs:
  tail -f /tmp/firebase_listener.log

  # Stop:
  pkill -f "firebase_chat_listener"

  Requires Firebase RTDB credentials configured.
  Handles: unread count updates, last_message sync, reaction aggregation.
  Run in a separate terminal alongside the backend + ARQ worker.

## Troubleshooting

### Flutter cache permission error

  If you see "Flutter failed to open a file at .../lockfile", run:

  sudo chown -R $(whoami) /home/shafkat/development/flutter/bin/cache/

### Hard refresh after code changes

  After a hot restart, the browser may still serve stale code.
  Do a hard refresh:
    - Chrome/Edge: Ctrl+Shift+R (or Cmd+Shift+R on Mac)
    - Firefox: Ctrl+Shift+R

### Port already in use

  If port 8080 or 8000 is already in use, kill the process:

  fuser -k 8080/tcp   # kill whatever is using port 8080
  fuser -k 8000/tcp   # kill whatever is using port 8000
